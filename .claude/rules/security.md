# セキュリティ規約

本フレームワークは「AI 時代のセキュリティリスク低減」が中核価値。セキュリティは機能要件と同格以上に扱う。

## OWASP Top 10 チェック（PR 前必須）

コミット・PR 作成前に security-auditor Agent による監査を通す。主要観点:

- **インジェクション / XSS**: 既定エスケープの迂回経路・`raw_html()` の不正当な使用・HTML 文字列直接組み立て
- **機微情報の露出**: エラーメッセージ・ログへの内部情報漏えい
- **セキュリティ設定ミス**: CI・Dockerfile・cargo-deny 設定の不備
- **脆弱な依存**: `cargo deny check advisories` の違反
- **SSRF / パストラバーサル**: サーバー層のリクエスト処理・静的ファイル配信

## 秘密情報の混入防止

- API キー・トークン・パスワード・秘密鍵をコード・設定・hooks・CI にハードコードしない
- `.env` 系ファイルをコミットしない（コミット前に staged 差分を確認）
- テストフィクスチャにも実クレデンシャルを使わない（ダミー値を明示）

## 本リポジトリ固有

- 依存追加は脅威面の拡大（PoC-2 脅威モデル参照）。上限（60 件・深さ 6）とともに `build.rs` の有無を確認する
- NPM 互換機能は `--ignore-scripts` を既定とする（サプライチェーン対策、REQ-12）
- `--no-verify` の使用禁止（pre-commit フックのバイパス禁止）
