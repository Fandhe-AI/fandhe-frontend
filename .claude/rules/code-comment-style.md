# コメント規約

## 目的

後続の読み手（Claude を含む）は渡された情報からしか判断できない。
コメントはクレート・モジュール視点での役割と、他クレート・他モジュールとの
文脈を埋め込み、ファイル単体で文脈が伝わる状態にする。

## 何を書くか

- このクレート・モジュール・関数の役割と責務境界（1〜2 行要約をドキュメンテーションコメントで）
- 呼び出し元・呼び出し先の文脈（「fandhe-frontend-server の SSR パスから呼ばれる」「core の `render()` を呼んでエスケープ済み HTML を返す」）
- 他クレートとの契約（例: 「この関数の出力は既定エスケープ済みであることを fandhe-frontend-server が前提とする」）
- 非自明な前提・副作用・エラー処理の意図
- セキュリティ上の不変条件（例: 「`raw_html()` 以外の経路では必ずエスケープされる」）
- `unsafe` ブロック（WASM/FFI 境界のみ許容）には安全性の根拠（`// SAFETY:`）を必ず書く

## 何を書かないか

- コードを読めば分かる逐語説明（`i += 1;  // i をインクリメント` 等）
- 陳腐化しやすい実装詳細の重複（コードと 2 重に管理しない）

## ドキュメンテーションコメントの形式

- Rust: クレート入口（`lib.rs`）に `//!`、公開 API に `///` を付ける。公開 API には必ず 1〜2 行の役割要約を付け、必要に応じて `# Examples` / `# Errors` / `# Safety` セクションを添える
- JavaScript（グルーコード・埋め込み HTML 内）: `/** */`
- コメント本文は日本語で書く（`.claude/rules/japanese-style.md` 参照）
