# rws プロジェクト（default テンプレート）

このプロジェクトは `fw new`（`default` テンプレート）から生成された rws
フレームワークの標準プロジェクトです。

- `src/main.rs`: アプリケーションのエントリポイント
- `structure.toml`: `fw gate` が唯一の情報源として読むノード木構造定義
- `Cargo.toml` / `Cargo.lock`: 依存パッケージ定義
- `tests/negative_type_error.rs`: 型不正コードが `cargo check` で機械的に
  弾かれることを確認する回帰テスト
- `tools/npm-asset-build/`: NPM 互換の静的アセットビルドゲート
- `.github/workflows/`: `cargo-deny` / NPM アセットゲートの CI ワークフロー

## セキュリティ既定（必読）

rws フレームワークは「AI 時代のセキュリティリスク低減」を中核価値とし、
既定で安全な出力を行います。本プロジェクトのコードを拡張する際は、以下の
既定動作を理解した上で実装してください。

### テキスト補間は既定エスケープを常に通過する

テキスト補間は必ず既定エスケープを経由します。エスケープを迂回する経路は
`raw_html()` 等の明示的なオプトイン API のみで、それ以外の経路でエスケープ
を回避することはできません。新たなエスケープ迂回経路を自作しないでくださ
い。

### URL 属性は許可スキーム検証を通過しないと出力されない

`href` / `src` 等の URL 属性（対象属性の正リストが定義されています）は、
レンダリング時に許可スキームかどうかの検証を通過した場合のみ出力されま
す。`javascript:` スキームやデータ URI などの危険なスキーム・偽装形を含む
値は、検証に不合格となった時点で **属性ごと出力されません**（fail-closed）。

動的に URL を組み立てる場合は、値を直接埋め込むのではなく、rws-core が提
供する URL スキーム検証（`is_safe_url`）を経由するノード木 API を使ってく
ださい。許可スキームの一覧は正本（rws-core 側の実装）を単一の情報源とし、
本プロジェクトのコード側にリストを複製しないでください。複製は将来の仕様
変更時にドキュメントと実装が乖離する原因になります。

### `on*` イベントハンドラ属性は一律不出力

`onclick` 等の `on` から始まるイベントハンドラ属性は、値の内容によらず一
律出力されません。イベント処理が必要な場合はフレームワークが提供する束縛
API を使い、カスタムのデータ属性が必要な場合は `data-*` を使ってくださ
い。

### HTML 文字列を直接組み立てない

`format!("<a href=\"{}\">", user_input)` のような HTML 文字列の直接組み立
ては行わないでください。既定エスケープや URL スキーム検証を迂回する経路
になります。必ずノード木 API を使ってください。

## 「属性が出力されない」場合の診断

意図した属性がレンダリング結果に現れない場合は、以下を確認してください。

1. 出力 HTML に該当属性そのものが存在するか（fail-closed の設計上、検証
   に不合格の場合は属性ごと出力されません）
2. URL 属性であれば、値が危険なスキーム（`javascript:` 等）や偽装形になっ
   ていないか
3. `on` から始まるイベントハンドラ属性を使っていないか（`data-*` へ置き
   換えてください）
