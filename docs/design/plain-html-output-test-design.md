## 2. 「素直さ」の機械判定可能な定義

PoC-3 の定性実測（`docs/spec/03-poc/rendering-web-standards/README.md` 第 6 節）
を、TASK-5.2b が `assert` 可能な形へ翻訳する。

1. **完全一致原則**: `rws_core::render()` の出力は、入力ノード木（タグ名・
   利用者指定の属性・エスケープ済みテキスト・`raw_html` 内容）から一意に
   導出される文字列と**完全一致**する。フレームワークによる要素・属性・
   コメント・マーカーの追加注入はゼロである。
2. **禁止パターン**: 出力に以下が「利用者が指定していない限り」現れないこと。
   - (a) フレームワーク固有カスタム要素（`<rws-` 等、他フレームワークの
     `<leptos-island>` 相当のカスタムタグ）
   - (b) HTML コメントマーカー（`<!--` を含む、hydration マーカー相当の
     コメント注入）
   - (c) フレームワーク接頭辞属性の自動付与（`data-rws-*` 等）
   - (d) 不透明な ID・ハッシュ属性の自動付与（`render()` が生成する
     ランダム値・連番 ID 等）
3. **許容範囲**: `data-*` 属性は**利用者・上位層が `attrs` で明示指定した
   場合のみ**、指定どおりに（エスケープ以外の変換なしで）出力される。
   `core` が自動付与する属性は現時点でゼロであり、この「ゼロである」こと
   自体をテストで固定する。

**既存契約との関係**: 本節は `core/src/lib.rs` 冒頭の不変条件（`docs/api/component-api.md`
第 6 節に再掲）を「出力に何を足さないか」の観点から補完するものであり、
既定エスケープ（不変条件 1〜3）の検証を代替しない（第 5 節参照）。

## 3. テスト観点一覧（TASK-5.2b が実装するケース表）

| # | 観点 | 検証方式 | 概要 |
|---|------|---------|------|
| T1 | 単一要素の完全一致 | 完全一致 assert | `el`+`text` の出力が入力から導出される文字列（例: `<p class="greeting">hello</p>`）と一致する |
| T2 | ネスト構造の完全一致 | 完全一致 assert | 深い入れ子（3 階層以上）でも要素・属性・コメントの追加注入がない |
| T3 | 禁止パターン不含 | 否定 assert（`!contains`） | 出力に第 2 節・禁止パターン定数集合（`<rws-`・`<!--`・`data-rws-` 等）が一切含まれない |
| T4 | `data-*` 許容側 | 完全一致 + 否定 assert | 利用者指定の `data-testid` 等が指定どおり出力され、かつ未指定の `data-*` が一切出現しない |
| T5 | PoC-3 相当の複合ノード木 | 完全一致 assert | list/detail 風の複合ノード木（PoC-3 実測ページ構造相当）を回帰スナップショットとして完全一致検証する |
| T6 | `raw_html` 使用時のマーカー非付加 | 完全一致 assert | `raw_html` の前後にも core がマーカー・ラッパー要素を注入しない（raw 内容がそのまま出力される） |
| T7 | 不正入力スキップ時のプレースホルダ非出力 | 完全一致 assert | 不正タグ名・不正属性名がスキップされる経路（`core/src/lib.rs` 不変条件 4・5）でも代替マーカー・プレースホルダ文字列を出力しない |
| T8 | タグショートカットの `el()` 等価性 | 完全一致 assert（TASK-5.1b 完了後有効） | `div`/`p` 等のショートカット出力が `el()` 直接使用時の出力と完全一致する。**TASK-5.1b（#31）完了後にのみ実装可能** |

### 検証方式の優先順位

- **完全一致 assert を第一**とする。禁止パターンの否定 assert だけでは、
  将来追加される新しい注入経路の検出漏れが起こり得るため、完全一致で
  「出力全体が期待どおりであること」を固定したうえで、T3 を横断的な
  補助チェックとして併用する。
- 禁止パターン集合は `const` 配列として定義し、`core/tests/xss_escape.rs` の
  `XSS_PAYLOADS` と同様に**削除・弱体化・`#[ignore]` 化を禁止**する。

## 5. TASK-5.2b への引き継ぎ事項

- 成果物パス: `core/tests/plain_html_output.rs`（親 #33 の成果物）。
- テストファイル冒頭 `//!` に担当タスク（TASK-5.2b・#35）・REQ-5 トレース・
  「本テストは既定エスケープ検証（`xss_escape.rs`）の代替ではなく補完で
  あり、削除・弱体化・`#[ignore]` 化を禁止する」旨を記載する
  （`xss_escape.rs` の規約踏襲）。
- T6（`raw_html`）の観点は「エスケープされないこと」の再検証ではなく
  「マーカー非付加」に限定する。`raw_html` の乱用を促す記述・コード例を
  設計書・テストのいずれにも書かない。
- コード例はノード木 API（`el`/`text`/`raw_html`/`render`）のみを用い、
  `format!("<div>{}</div>", ...)` のような HTML 文字列直接組み立ての例を
  一切含めない（`.claude/rules/coding-rust.md`）。
- T8 は TASK-5.1b（#31）のタグショートカットのマージ後にのみ実装可能。
  TASK-5.2b 着手時点で未マージの場合は T8 を除く T1〜T7 を先行実装し、
  T8 の追補を #31 完了後のフォローとして記録する。

## 7. セキュリティ考慮事項（OWASP Top 10 観点）

- **A03 インジェクション / XSS**: 本設計は既定エスケープの仕様を変更しない。
  素直さ検証は既定エスケープ検証（`xss_escape.rs`）の代替ではなく補完である
  ことを第 5 節に明記した。設計書のコード例はノード木 API のみを用い、
  HTML 文字列直接組み立ての例を一切載せていない。
- **A05 セキュリティ設定ミス**: CI・フック設定は変更しない。
- **A06 脆弱な依存 / サプライチェーン**: 依存クレートの追加はゼロ
  （docs-only）。`core` の外部依存ゼロ・依存グラフ上限（60 件/深さ 6）に
  影響しない。
- **機微情報の露出**: 本書・想定コード例に API キー・トークン・実在の
  内部情報を含まない。TASK-5.2b で使用するペイロード・フィクスチャは
  すべてダミー値とすること。
- **A08 ソフトウェアとデータの整合性**: 本書は「実装（TASK-5.2b）と本書が
  乖離した場合は本書を正とする」ステータスを第 1 節に明記し、レビューで
  整合を強制する（TASK-5.1a と同じ運用）。
